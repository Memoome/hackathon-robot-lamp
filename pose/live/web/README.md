# 本机网页摄像头客户端

在仓库根目录运行（沿用 `pose/live/requirements.txt` 的 pyserial 依赖）：

```sh
python3 pose/live/host/web_camera.py --port 8768
```

打开 <http://127.0.0.1:8768>，点击「开始查看」。服务仅监听本机回环地址，
不上传画面，不自动刷机。使用兼容的 live-pose 固件、921600 波特率；
启动网页本身不会打开串口。

提供开始、停止、旋转选择、当前原始预览下载（不含标注）、更新间隔、画面年龄和错误详情。
显示的 PNG 来自校验通过的 UYVY 帧，不做自动调色。默认显示板端模型返回的人体框、骨架和关键点，可取消勾选查看原图；不补造缺失点。面板显示人数、各人体置信度、有效关键点数、推理耗时及完整 JSON。
串口会话只有一个；重复点击不会启动多个读取器。当前固件包含板端推理，
每轮通常约 8–10 秒，不是流畅视频。推理结束后将画面和结果作为一个完整快照发布；等待下一轮时保留上一帧对应结果。快照内嵌图像，避免两个 HTTP 请求跨帧导致标注错位。

坐姿判断（实验）：每帧推理结果都会交给 `host/posture.py` 的 `PostureMonitor`。开始查看后点「校准坐姿」，以舒适坐姿采 3 帧作为基线；之后按肩部倾斜、头部降低、躯干侧倾与基线比较，偏离持续 30 秒且至少 3 帧才显示「持续提醒」。画面中须恰好一人；停止或换方向会清除校准。

- `GET /api/posture`：最新坐姿结果（`summary`、`details`、`frame_id`、`calibrating`、`calibrated`、`baseline`、`stale`）。`/api/state` 的 `posture` 字段相同。
- `POST /api/calibrate`（JSON 请求体，可为 `{}`）：开始校准；未在查看时返回 400。

采集错误后停止，不无限重连；用户准备好后可点「重新连接」。旧画面会保留，
但明确显示非实时标记。网页服务或浏览器断开也会标注旧图。默认照片仅保留
最近一帧在内存中，不读取历史照片作实时预览；显式下载才保存到浏览器。
诊断日志仍存放在 Git 忽略的 `pose/live/evidence/`。

关闭所有预览页后，30 秒内未收到页面心跳会请求停止；等待当前采集/推理和
停止确认结束后释放串口。点击「停止」可立即发出停止请求。保持服务运行
即可再次打开网页。退出服务可用 Ctrl+C。

验证：

```sh
python3 -B -m unittest discover -s pose/live/host -p 'test_*.py'
```

网页客户端不代表硬件采集已稳定；若传感器或取帧失败，界面展示真实错误。
